# ④ 신호 상태 안정화 실험 (smoother)

- 질문: 프레임마다 흔들리는 원시 상태를 ⑤ 제어에 넘길 수 있는 **확정 상태** 로 만들 수 있는가
- 기간: 2026-11-01 ~ 2026-11-08, DESKTOP (WSL, RTX 5070 Ti Laptop 12GB)
- 단일 이미지 test 로는 측정할 수 없어 **영상 프레임 순서** 로 평가

## 1. 조건

| 단계 | 사용한 것 | 학습 여부 |
|---|---|---|
| ① 검출 | det_vehicle_other `--det-classes 0`, conf 0.25, imgsz 1280 | 파인튜닝 |
| ③ 판별 | E03 (7클래스), imgsz 224 | 파인튜닝 |
| ② 대상 선택 | `selector.py` 기본값 | 규칙 |
| ④ 안정화 | `smoother.py` 시작값 (3장) | **규칙** (학습 모델 아님) |
| 영상 | `drive.mp4` 1920×1080, 60 fps, 263.3초, 15,797프레임 (서울 도심 주간) | – |

- 기준값은 **시작값 그대로** (조정하지 않음). 영상이 1개라 조정용 / 검증용을 나눌 수 없음 (7장)

## 2. 평가 방법

| 순서 | 스크립트 | 내용 | 실행 |
|---|---|---|---|
| 1 | `tools/record_states.py` | 영상 전체를 ① → ③ → ② 처리, 프레임별 원시 상태를 csv 로 저장 (시각 = 프레임 번호 / 영상 fps) | GPU, 1번만 |
| 2 | `smoother.py` | 원시 상태 → 확정 상태 (cv2, YOLO 없음) | – |
| 3 | `tools/replay_smoother.py` | csv 를 다시 읽어 기준값 조합별 지표 비교, 타임라인 그림 | GPU 불필요 |

```bash
python tools/record_states.py --source drive.mp4 --model $BEST --det-classes 0 --cls-model $E03 --csv <states.csv>
python tools/replay_smoother.py --csv <states.csv> --plot smooth_timeline.png
```

- 지표: `changes` 상태 변화 횟수 / `short` 0.2초 미만 구간 수 / `shown` NONE 이 아닌 프레임 비율 / `delay` 원시 상태가 바뀐 뒤 확정까지 평균 시간. 구간 정답 (`--gt`) 이 있으면 `acc`, `danger` (정답은 정지 쪽인데 출발 쪽으로 확정된 시간), `false_stop`

## 3. 방식 C + D (시간 창 비율 투표 + 비대칭 확정)

- 유효 관측 (6상태) 만 투표. UNKNOWN, NONE 은 투표에서 빼고 확정 상태 유지
- 새 상태 X 확정 조건 (모두 만족)
  1. X 가 T(X) 초 이상 보임 (처음 보인 시각부터, hold 보다 긴 공백이면 다시 셈)
  2. 최근 T(X) 초 유효 관측 중 X 비율 ≥ ratio
  3. X 개수 ≥ 최소 관측 수 (= min_obs × T × 처리 fps)
- 마지막 유효 관측 후 hold 초가 지나면 NONE (중립)

| 그룹 | 상태 | 확정 시간 | 이유 |
|---|---|---|---|
| 정지 쪽 | RED, YELLOW, RED_LEFT | **t_stop 0.2초** (빠르게) | 늦은 정지가 위험 |
| 출발 쪽 | GREEN, GREEN_LEFT, LEFT | **t_go 0.5초** (천천히) | 잘못된 출발이 가장 위험 → 녹색이 확실할 때만 |

| 기준값 | 시작값 | 60 fps 환산 |
|---|---|---|
| t_stop / t_go | 0.2 / 0.5초 | 12 / 30프레임 |
| ratio | 0.7 | – |
| min_obs | 0.3 | 4 / 9프레임 |
| hold | 1.5초 | 90프레임 |
| red_hold (옵션 E: 확정 RED → YELLOW 전환 막기) | 꺼짐 | – |

## 4. 결과

### 4.1 원시 상태 기록

- 11.9 ms/프레임 (84.2 fps, 중앙값 9.7 ms) → 60 fps 영상 실시간 처리 가능
- 원시 상태 분포: NONE 59.7%, RED 19.5%, GREEN 18.7%, RED_LEFT 1.6%, YELLOW 0.5%, UNKNOWN 0.1%, LEFT 1프레임

### 4.2 smoother 적용 (시작값)

| 지표 | 원시 | 확정 |
|---|---|---|
| 상태 변화 횟수 | 129 | **25** |
| 0.2초 미만 구간 | 94 (72%) | **0** |
| NONE 아닌 프레임 비율 | – | 45.3% |
| 평균 확정 지연 | – | 0.31초 |

- 원시 짧은 구간 94개: NONE 23, YELLOW 20, RED_LEFT 19, RED 19, GREEN 9, 그 외 4
- 옵션 E 켬 / 끔 결과 같음 (drive.mp4 에 확정 RED → YELLOW 오판 상황 없음)

### 4.3 가상 시퀀스 시험 (60 fps, smoother 단독)

| 상황 | 결과 |
|---|---|
| NONE → GREEN / NONE → RED | 0.5초 / 0.2초 뒤 확정 |
| GREEN → YELLOW → RED | 각 0.2초 뒤 전환 |
| RED 중 1프레임 GREEN 튐 × 5 | RED 유지 |
| GREEN 중 검출 0.5초 끊김 | GREEN 유지 |
| 신호등 사라짐 | 1.5초 뒤 NONE |
| 황색 점멸 0.5초 켜짐 / 꺼짐 | YELLOW 유지 |
| 신호 없는 구간 오검출 GREEN 0.3초 | 확정 안 됨 |
| RED 중 YELLOW 오판 30% 섞임 | RED 유지 |
| RED 중 YELLOW 오판 0.3초 연속 | E 끔: YELLOW 0.23초 / **E 켬: RED 유지** |

## 6. 분석

- 프레임 단위 흔들림 (1프레임 튐, 짧은 검출 끊김, 상태 오판 섞임) 은 smoother 로 해결
- 남은 오동작은 **② 대상 선택** 에서 생김 (101초, 165초): 고정 높이 기준 (`max_center_y` 0.55) 이 정면 신호등을 버리고, selector 가 진행 방향을 모름
- "황색 + 화살표" 는 ③ 판별 클래스 밖. 현재 출력 (YELLOW / RED_LEFT) 은 정지 쪽이라 안전

## 7. 한계와 다음 결정

- 영상 1개, 실제 신호 전환 3번, 황색 1번 → **기준값을 정하거나 검증하기에는 장면 수 부족**. 구간 정답 (gt) 미작성
- 기준값은 시작값 유지. 조정은 **조정용 영상에서 정하고, 고르지 않은 검증용 영상에 바꾸지 않고 적용** (영상마다 다시 조정하지 않는 것이 목표)
  - 필요 장면 수 (조정용 / 검증용): 황색 전환 5~10 / 3~5번, 적 → 녹 출발 5 / 3번 이상, 신호등 접근 20 / 10번 이상
  - 촬영 조건: 1920×1080, 60 fps (30 가능), 앞 유리 가운데 고정, 정면, 수평
- 비교 후보: hold 1.0 / 1.5 / 2.0, min_obs 0.3 / 0.15 / 0, t_go 0.3 / 0.5 / 0.8, 옵션 E 0 / 1
- selector 재검토: `max_center_y` 0.60 / 0.65 (`record_states.py --max-cy`), 진행 방향 반영은 ⑤ 방향 의도 입력과 함께
- "황색 + 화살표" 처리 (추천 YELLOW) 는 ⑤ 제어에서 결정
