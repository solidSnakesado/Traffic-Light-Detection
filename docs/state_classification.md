# ③ 신호 상태 판별 실험 (E01 ~ E03)

- 질문: 신호등 박스가 주어졌을 때 상태(RED, YELLOW, GREEN, LEFT, RED_LEFT, GREEN_LEFT)를 맞히는가
- 비교 C3: **정답 박스** 기준 (검출 단계 영향 없음). 전체 흐름(검출 박스) 결과는 `detection_and_flow.md`
- 기간: 2026-10-18 ~ 2026-10-25, DESKTOP (WSL, RTX 5070 Ti Laptop 12GB)

## 1. 공통 조건

| 항목 | 값 |
|---|---|
| 데이터 | AI Hub 신호등 신호정보 인지 영상, Validation 10,000장 |
| 분할 | Clip 단위 train 70 / val 15 / test 15, seed 0 (`tools/convert_labels.py`) → test 1,500장 |
| 평가 박스 | test 정답 박스 (클래스 0~5) 4,536개 / 그중 selector 1단계 통과 3,914개 |
| 라벨 배정 | red and yellow, green and yellow → YELLOW. etc, 화살표 2개, 아래 화살표, 버스 → other (평가 제외) |
| 지표 | 정확도 = 맞힌 상태 / 전체 박스 (UNKNOWN 은 오답), 거부율 = UNKNOWN / 전체 |

## 2. 실험 구성

| ID | 판별 방법 | 학습 여부 | 데이터 | 스크립트 |
|---|---|---|---|---|
| E01 | HSV 색 규칙 `classifier.py` | 학습 없음 (규칙) | – | `tools/eval_hsv.py` |
| E02 | `yolo26n-cls` 6클래스 | ImageNet 사전학습 → 잘라낸 정답 박스로 **파인튜닝** | `~/datasets/traffic_light_cls` (train 20,108) | `tools/make_crops.py`, `tools/train.py`, `tools/eval_cls.py` |
| E03 | `yolo26n-cls` 7클래스 (+NONE) | 같음 | `~/datasets/traffic_light_cls_none` (train 92,632 = 정답 박스 + 흔든 사본 + NONE) | `make_crops.py --none --jitter 1` |

- E02 / E03 학습 설정 (같음): imgsz 224, batch 64, 30 epoch, seed 0, AdamW lr 0.001. fliplr, hsv_h, erasing, scale, auto_augment 끔 (색과 좌우 방향이 상태 정보), hsv_s 0.7, hsv_v 0.4 유지
- 잘라내기: 박스를 정사각형 회색 여백으로 패딩
- E03 흔들기: 너비·높이 0.9~1.3배, 중심 ±10% (train 만). NONE = invisible, pedestrian, other 박스

## 5. 오류 분석

| ID | 주된 오류 | 원인 |
|---|---|---|
| E01 | 판별 거부 (UNKNOWN) 34.7%, 특히 RED 642 / GREEN 620 | 시연 영상에 맞춘 색 기준값이 다양한 환경(AI Hub: 야간, 역광, 거리)에 일반화되지 않음. 답을 낸 경우만 보면 92.5% |
| E01 | GREEN_LEFT → GREEN 149 | 4구 화살표를 칸 단위 색 비율로 구분하지 못함 |
| E01 | red and yellow 60개 모두 UNKNOWN | 규칙표에 적 + 황 조합이 없음 (구조적) |
| E02 | RED ↔ YELLOW 혼동 (39 / 27) | 적색과 황색의 색 차이가 작은 장면 (번짐, 역광) |
| E02 | 신호등이 아닌 박스도 6상태 중 하나로 답함 | 학습 데이터에 "신호 아님" 이 없음 → 실제 검출 박스(보행자 신호, 측면, 표지판)에서 문제 |
| E03 | 상태 박스 → NONE 75개 (1.7%, GREEN 51) | NONE 클래스 추가로 생긴 새 오류. E02 대비 정확도 −0.9%p 의 주된 원인 |
| E03 | **NONE → GREEN 30개 (0.5%)** | 신호 아닌 박스를 녹색으로 판단. 가장 위험한 오류 (잘못된 출발) → ④ 안정화에서 출발 쪽을 천천히 확정 |

- selector 통과 박스의 정확도가 전체보다 높음 (E02 98.3 vs 97.1) → 작거나 세로형·잘린 박스에서 오류가 많음

## 6. 결정

| 시점 | 결정 | 이유 |
|---|---|---|
| E01 후 | HSV 기준값은 조정하지 않고 비교 기준으로 사용 | 영상마다 기준값을 맞추는 방식은 일반화 문제를 해결하지 못함 |
| E02 후 | NONE 클래스 + 박스 흔들기 추가 (E03) | 실제 파이프라인은 정답 박스가 아니라 검출 박스가 들어옴 |
| E03 후 | **E03 채택** (`runs/classify/state_cls_none/weights/best.pt`) | 정확도 −0.9%p 대신 신호 아닌 박스 98.4% 거름. 전체 흐름(C4)에서 효과 확인 |
